Mathematical Foundation
Object graph forms a DAG — no cycles, no surprises
▌ WHAT — formal dependency graph
Classes form a directed acyclic graph $\mathcal{G}=(V,E)$ with $V$ = classes and $E$ = composition/implementation edges. Topological depth is the construction order:
$\begin{aligned} 0 &:\ \text{protocols (no deps)} \\ 1 &:\ \text{types, exceptions} \\ 2 &:\ \mathrm{BaseModelAdapter},\ \text{mechanisms} \\ 3 &:\ \mathrm{SklearnRF},\ \mathrm{XGBoost},\ \ldots \\ 4 &:\ \mathrm{SoftLabelGen},\ \mathrm{SurrogateDistiller} \\ 5 &:\ \mathrm{FederatedClient},\ \mathrm{Aggregator} \\ 6 &:\ \mathrm{FederatedCoordinator} \\ 7 &:\ \mathrm{ExperimentRunner}\ \text{(composition root)} \end{aligned}$
$\forall\, e=(u,v) \in E:\; \mathrm{depth}(u) \ge \mathrm{depth}(v),\quad \mathcal{G}\ \text{acyclic} \Rightarrow \exists!\ \text{init order}$
# $|V| \approx 30$, $|E| \approx 60$
▌ WHY — the abstract base class layer
BaseModelAdapter exists for one reason: to eliminate boilerplate. The refit guard, binary→2D reshape, and safe-pickling sub-protocol are identical across sklearn / XGBoost / LightGBM / CatBoost. Replicating them is bug-prone; inheriting them is cheap.

Concrete adapters override only the two methods that genuinely differ between backends: _fit_impl and _predict_proba_impl. Five lines of code per new framework.

This is the only place inheritance survives — and only for behaviour that is mechanically the same.
▌ MINDSET — favour composition over hierarchy
Look at FederatedClient: it has seven dependencies stored as fields. It owns none of them — they are injected by the runner from typed config.

"Has-a" everywhere, "is-a" almost nowhere. The only "is-a" relationship is the protocol-implementation arrow, which is structural and reversible at runtime.

Read the UML edges as a wiring diagram, not a taxonomy. They tell you what plugs into what; they do not declare ontology.

The dependency DAG
\(\mathcal{G}=(V,E)\)
Directed acyclic graph of class dependencies; vertices = classes/protocols, edges = composition or implementation arrows.
Realised by Python import graph + constructor injection in orchestration/runner.ExperimentRunner. Verified acyclic at module load (ImportError on cycle).
\(V\)
Vertex set — every concrete or abstract class shown in the UML pane (\(|V|\approx 30\)).
Protocols in core/protocols.py; concretes in client/, coordinator/, distillation/, privacy/, aggregation/, meta/, data/.
\(E\)
Edge set — \((u,v)\in E\) means class \(u\) holds a field of (or implements) class \(v\) (\(|E|\approx 60\)).
"Has-a" edges = constructor params on each class; "is-a" edges = Protocol implementation declarations.
\(e=(u,v)\)
A single directed edge from dependent \(u\) to dependency \(v\) — read as "\(u\) needs \(v\) constructed first".
E.g. FederatedClient → SoftLabelGenerator appears as self.soft_label_generator field.
Topological depth
\(\mathrm{depth}(v)\)
Length of the longest path in \(\mathcal{G}\) from a source (no-dependency) vertex to \(v\). Defines construction order.
Implicit in the order of ExperimentRunner.__init__ — protocols (0), exceptions (1), BaseModelAdapter (2), concretes (3), distiller/soft-label-gen (4), client/aggregator (5), coordinator (6), runner (7).
\(\forall e=(u,v):\ \mathrm{depth}(u)\ge\mathrm{depth}(v)\)
Acyclicity / monotonicity condition — every dependency is constructed before its dependent.
Enforced by the order of factory calls in runner._build_* helpers; failure would raise NameError at composition time.
\(\exists!\ \text{init order}\)
Existence and uniqueness (up to ties) of a topological ordering — guaranteed by acyclicity.
orchestration/runner.py hardcodes one such order; tests in tests/test_runner_bootstrap.py verify deterministic construction.
Concrete vertex classes (named in the depth ladder)
\(\mathrm{BaseModelAdapter}\)
Abstract class encapsulating refit guard, binary→2D reshape, and safe-pickling sub-protocol shared across backends.
core/adapters/base.py:BaseModelAdapter — subclasses override only _fit_impl and _predict_proba_impl.
\(\mathrm{SklearnRF},\ \mathrm{XGBoost},\ \ldots\)
Concrete adapters at depth 3 — one per ML backend (sklearn RF, XGBoost, LightGBM, CatBoost, sklearn DT).
core/adapters/{sklearn_rf,xgboost,lightgbm,catboost,sklearn_dt}.py.
\(\mathrm{SoftLabelGen},\ \mathrm{SurrogateDistiller}\)
Depth-4 building blocks: produce \(P_k\) from a teacher, and distil \(\tilde{P}_k\) into a tree \(S_k\).
distillation/soft_labels.py:SoftLabelGenerator, distillation/surrogate.py:SurrogateDistiller.
\(\mathrm{FederatedClient},\ \mathrm{Aggregator}\)
Depth-5 composites — client owns teacher+distiller+DP+meta; aggregator combines client updates on the proxy.
client/client.py:FederatedClient; aggregation/{proxy_redistillation,confidence_weighted,majority_vote}.py.
\(\mathrm{FederatedCoordinator}\)
Depth-6 — orchestrates a round: validate updates → aggregate → record privacy spend → emit GlobalArtifact.
coordinator/coordinator.py:FederatedCoordinator.round().
\(\mathrm{ExperimentRunner}\)
Depth-7 composition root — reads config, instantiates every other vertex, drives the federation loop.
orchestration/runner.py:ExperimentRunner; entry point in experiments/scripts/run_*.py.
Invariant. Acyclicity of \(\mathcal{G}\) plus the depth function gives a unique safe construction order — which is precisely why dependency injection works without a framework: a single linear scan through ExperimentRunner.__init__ builds the entire world from typed config.
