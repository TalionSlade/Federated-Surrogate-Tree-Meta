Mathematical Foundation
Why mixed backends still aggregate
▌ WHAT — the adapter interface as a category
Each backend is an object in the category Tree. Adapters are morphisms into the shared codomain — the probability simplex \(\Delta^{K-1}\):
$$A : \mathbb{R}^{d} \;\longrightarrow\; \Delta^{K-1}$$ $$\sum_{j=1}^{K} A(x)_j = 1,\quad A(x)_j \ge 0$$
# Interchangeability theorem
$$\forall\, A, B : \mathbb{R}^d \to \Delta^{K-1},\quad \mathrm{aggregate}(\{A, B\})\ \text{is well-defined}$$
# Communication bound
$$|\text{wire}| \;\le\; |\mathrm{pickle}(A)| \;\le\; \text{depth} \cdot n_{\text{leaves}} \cdot 8\ \text{B} \;\approx\; 10\ \text{KB}$$
▌ WHY — different backends are fine
Tree weights are not parameters in a shared space. sklearn's split thresholds, XGBoost's leaf values, LightGBM's leaf-wise structure, CatBoost's ordered boosting — these objects have no common arithmetic. FedAvg-style mean is meaningless.

What is common is the output: a probability vector summing to 1. Two clients running totally different backends can both project onto the same simplex.

Aggregation happens in the simplex — that's why ProxyRedistillationAggregator works regardless of who-trained-what.
▌ MINDSET — protocols > inheritance
Inheritance binds you to the framework you started with. We use Python's typing.Protocol — structural typing — so anything that walks like a tree is a tree.

The safe-deserialiser is the trust boundary. Coordinator imports the class path before unpickling, refuses anything that doesn't implement ModelAdapterProtocol. This prevents arbitrary-code-execution through a malicious pickle.

Bandwidth is the wire format's only metric. Pickle is small enough for tree weights; future formats (ONNX, native JSON) plug into the same protocol.
