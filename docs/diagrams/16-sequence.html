Mathematical foundation
A round is a partially-ordered set of typed messages
▌
WHAT
Each arrow is a message $m_t : \mathrm{actor}_i \to \mathrm{actor}_j$ with a payload type and an optional return $r_t$. The lifeline is a partial order $\preceq$ over messages (causal precedence).
$\begin{aligned} m_1 &: \mathrm{Client} \to \mathrm{Self} &&\mathrm{teacher.fit}:(X,y)\to\checkmark \\ m_2 &: \mathrm{Client} \to \mathrm{Self} &&\mathrm{predict\_proba}: X \to P\in\Delta^{K-1} \\ m_3 &: \mathrm{Client} \to \mathrm{DP} &&\mathrm{privatize}:(P,\varepsilon,\delta) \to \tilde{P} \\ m_4 &: \mathrm{Client} \to \mathrm{Distiller} &&\mathrm{distill}:(X,\tilde{P})\to S \\ m_5 &: \mathrm{Client} \to \mathrm{Coord} &&\mathrm{upload}: \mathrm{ClientUpdate}\to\checkmark \\ m_6 &: \mathrm{Coord} \to \mathrm{Aggregator} &&\mathrm{aggregate}: [S_k] \to G \\ m_7 &: \mathrm{Coord} \to \mathrm{Acct} &&\mathrm{record}:(t,[\varepsilon_k,\delta_k])\to(\varepsilon_c,\delta_c) \\ m_8 &: \mathrm{Coord} \to \mathrm{Client}_K &&\mathrm{broadcast}: G \to \checkmark \\ m_9 &: \mathrm{Client} \to \mathrm{Meta} &&\mathrm{refine}:(X,y,G)\to M_k \end{aligned}$
$m_1 \preceq m_2 \preceq m_3 \preceq m_4 \preceq m_5,\quad \forall k.\ m_5^k \preceq m_6 \preceq m_7 \preceq m_8,\quad m_8 \preceq m_9$
▌
WHY

Sequence diagrams reify time. Object diagrams show which objects exist; sequence diagrams show when they speak — and "when" is the only thing that gates DP composition.

Why visualise the round, not the whole experiment? Because the round is the unit of privacy accounting: every red arrow (DP component) maps to exactly one row in the ledger, every amber arrow (server) is a non-privacy operation, and the cumulative (ε_cum, δ_cum) grows only across red arrows.

Why explicit return arrows? A return type that doesn't match the caller's expectation is the most common federation bug — surfacing → P̃ and → S on the wire makes adapter type-mismatches a diagram-time error, not a run-time crash.

▌
MINDSET

Explicit data flow over hidden state. If you can't draw it on a lifeline, it's invisible to audits. Hidden global mutations — singletons, side-effects, shared scratchpads — break the message-passing invariant and corrupt the accountant.

Phases are contracts, not suggestions. The five phases (LOCAL TRAIN → UPLOAD → AGGREGATE → BROADCAST → META REFINE) admit no overlap: phase boundaries are synchronisation barriers. Asynchronous variants must coarsen, never reorder.

Privacy lives on the wire. Every byte that crosses a process boundary needs an answer to "what is its sensitivity Δ?" The red privatize() arrow is the only place sensitivity is bounded — everything downstream is post-processing and therefore free.

∎ Round invariant: the round is correct iff {m₃, m₇} (the only red arrows) form a privacy-consistent prefix: ε_cum after m₇ ≤ target_budget, and m₃ has been applied to every probability vector that later leaves Client_k.

Per-message payloads
\(X, y\)
Client \(k\)'s private feature matrix and label vector consumed by teacher.fit in \(m_1\).
self.X_local, self.y_local on FederatedClient.
\(P\)
Raw teacher posteriors emitted by \(m_2\); row in \(\Delta^{K-1}\).

\(\tilde P\)
Privatised soft labels — the return of \(m_3\); the only noised object on the wire.
self.dp_mechanism.privatize(P, ε, δ) in privacy/mechanisms.py.
\(\varepsilon, \delta\)
Per-round privacy budget pair passed as the second/third args to \(m_3\) and recorded in \(m_7\).
cfg.dp.target_epsilon/n_rounds and cfg.dp.target_delta.
\(S\)
Per-client surrogate tree — return of \(m_4\); payload of \(m_5\).
self.distiller.distill(X, P̃, classes); wrapped in ClientUpdate.surrogate_blob.
\(\mathrm{ClientUpdate}\)
Wire dataclass uploaded in \(m_5\) — contains \(S_k\), \(n_k\), per-client \((\varepsilon_k, \delta_k)\), and a tag.
protocol.client_update.ClientUpdate.
\([S_k]\)
List of all client surrogates received this round — input to the aggregator in \(m_6\).
updates: list[ClientUpdate] on the coordinator.
\(G\)
Global model — return of \(m_6\), broadcast payload of \(m_8\), feature provider in \(m_9\).
aggregator.aggregate(updates, proxy_X, classes); wrapped as GlobalArtifact.
\(\varepsilon_c, \delta_c\)
Cumulative privacy spend returned by the accountant in \(m_7\). Compared against the run budget for fail-fast termination.
accountant.record(t, per_client_eps).cumulative() in privacy/accountant.py.
\(M_k\)
Refined client model — return of \(m_9\); locally retained, never re-broadcast.
StackingMetaLearner.refine(X, y, G, teacher_factory).
Partial-order constraint
\(\preceq\)
Causal precedence — \(m_a \preceq m_b\) means \(m_a\) must complete before \(m_b\) starts. The lifeline is a partial order, not a total order, because client-side messages can interleave across \(k\).
Enforced by sequential method calls; coordinator awaits all m_5^k via the synchronous round() barrier before \(m_6\).
\(m_5^k\)
Client-\(k\) instance of the upload message \(m_5\). The "for all \(k\)" quantifier makes the barrier explicit.
One upload() call per client; gathered into updates at the top of Coordinator.round.
Note. The lifeline is a contract about when things happen — the only invariant that matters for DP composition. The two red arrows \(m_3\) (privatize) and \(m_7\) (record) form the privacy-consistent prefix: every byte that leaves Client_k has been through \(m_3\); every round contributes exactly one row to the accountant via \(m_7\).
