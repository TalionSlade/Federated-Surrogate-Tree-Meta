BasicCompositionAccountant

linear bound · mechanism-agnostic
# After T rounds with per-round (εᵢ, δᵢ) ε_total = Σᵢ εᵢ δ_total = Σᵢ δᵢ # Records every privatize call ledger : list[PrivacyLedgerEntry] cumulative() → (ε_total, δ_total)
PROS
+ Works for any DP mechanism (Lap, Gauss, future).
+ Trivially auditable — just a sum.
+ No hyperparameters.
CONS
− Linear growth ⇒ wasteful for many rounds.
− Doesn't exploit Gaussian's subgaussian tail.

RDPAccountant (Gaussian-specialised)

Rényi-DP · Mironov 2017
# For each round with noise multiplier σᵢ / Δ₂ α-RDP: ε(α) = Σᵢ α / (2 · μᵢ²) where μᵢ = σᵢ / Δ₂ # Convert RDP → (ε, δ)-DP ε_DP = minα > 1 [ ε(α) + ln(1/δ) / (α-1) ]
PROS
+ Sub-linear growth for Gaussian ⇒ many more rounds at same ε.
+ State of the art for analytic Gaussian composition.
+ α grid is automatic (1.5 … 64).
CONS
− Gaussian only (in this codebase).
− Requires recording σ per round (handled internally).
