Mathematical Foundation
Protocols are equivalence classes of behaviour
▌ WHAT — substitution principle
A protocol \(\mathcal{P}\) is a set of method signatures. Any object \(o\) with the right shape is in \(\mathcal{P}\). Liskov-style substitutability is enforced at the type-checker:
$$o : \mathcal{P} \;\Longleftrightarrow\; \forall\, m \in \mathrm{sigs}(\mathcal{P}).\; \mathrm{hasattr}(o, m)\,\wedge\, \mathrm{type}(o.m) \subseteq \mathcal{P}.m$$
# Composition closure
$$\mathcal{P}_{\text{Client}} \;\supseteq\; \mathcal{P}_{\text{Adapter}} \cup \mathcal{P}_{\text{DP}} \cup \mathcal{P}_{\text{Distil}} \cup \mathcal{P}_{\text{Meta}}^{?}$$
# Result: \(O(1)\) swap cost — any impl change does not ripple through code
▌ WHY — no inheritance
A research codebase has churn rates of 5–10× a production system. Inheritance trees freeze design decisions; protocols invite experimentation.

Each protocol corresponds to a paper question. Want to ablate DP? Implement DPMechanismProtocol. Want to test a new aggregator? Implement AggregatorProtocol. The runner doesn't change.

8 protocols × ~3 impls each = 6,561 wire-compatible experiments, all from one runtime.
▌ MINDSET — type the contract, not the implementation
A protocol declares what something does, not what it is. No isinstance checks anywhere in the codebase — duck typing with teeth.

The composition root (orchestration) is the only place that sees concrete classes. Below it, every reference is via a protocol. This is the dependency-inversion principle made physical.

Tests use protocol implementations directly — a fake DP mechanism, a stubbed aggregator. No mocks library required.

Substitution principle
\(\mathcal{P}\)
A protocol — a finite set of method signatures (name + types) describing a behavioural contract. Implementations are not classes that inherit; they are objects that satisfy the signatures structurally.
Declared with typing.Protocol in protocols/*.py (e.g. ModelAdapterProtocol, DPMechanismProtocol).
\(o\)
A candidate object — any Python instance. \(o : \mathcal{P}\) reads "o satisfies the protocol P".
Constructed by factories in orchestration/factories.py; passed positionally into the runner.
\(o : \mathcal{P}\)
The membership relation — \(o\) is a witness of protocol \(\mathcal{P}\) iff it carries every required method with a compatible signature.
Enforced statically by mypy --strict; never via isinstance at runtime.
\(m\)
A method (name and type signature) required by the protocol — e.g. privatize(P, eps, delta) -> np.ndarray.
Declared as a method stub inside the Protocol body.
\(\mathrm{sigs}(\mathcal{P})\)
The set of all method signatures the protocol requires. The minimal contract surface.
Introspected by typing.get_type_hints(Protocol); used in test scaffolding under tests/protocols/.
\(\mathrm{hasattr}(o, m)\)
The structural existence check: does the object expose this method? Necessary condition for \(o : \mathcal{P}\).
Implicit at protocol-attribute access; type-checker enforces presence statically.
\(\mathrm{type}(o.m) \subseteq \mathcal{P}.m\)
Subtyping condition: the object's method signature must be a subtype (covariant in returns, contravariant in args) of the protocol's signature.
Variance enforced by mypy; runtime witnesses are exercised by per-protocol contract tests.
Composition closure — the runner's contract
\(\mathcal{P}_{\text{Client}}\)
The aggregate protocol the federation runner depends on to instantiate a client. It is the superset of every sub-protocol the client must compose.
protocols/client.py::ClientProtocol — the runner's only client-side dependency.
\(\mathcal{P}_{\text{Adapter}}\)
Tree-model adapter contract: fit, predict_proba, classes_. Required so the client can wrap any backend.
protocols/adapter.py::ModelAdapterProtocol; satisfied by SklearnTreeAdapter, XGBoostAdapter, …
\(\mathcal{P}_{\text{DP}}\)
DP mechanism contract: privatize(P, eps, delta) -> P̃. The only randomised arrow in the pipeline.
protocols/dp.py::DPMechanismProtocol; satisfied by LaplaceMechanism, GaussianMechanism, NullDPMechanism.
\(\mathcal{P}_{\text{Distil}}\)
Surrogate-distillation contract: distill(X, P̃, classes) -> BaseModelAdapter. Maps soft-labels to a small student tree.
protocols/distillation.py::DistillerProtocol; satisfied by SurrogateDistiller.
\(\mathcal{P}_{\text{Meta}}^{?}\)
Optional meta-learner contract: refine(X, y, G, factory) -> StackedAdapter. The "?" marks it as optional — clients may skip stacking.
protocols/meta.py::MetaLearnerProtocol; satisfied by StackingMetaLearner or omitted entirely.
\(\supseteq\)
Protocol-superset: \(\mathcal{P}_{\text{Client}}\) requires at least the union of the sub-protocol contracts — possibly more (e.g. local_train, id).
Composition closure enforced by FederatedClient's constructor type signature.
\(\cup\)
Set union of signature sets — when composing sub-protocols into the client contract, their required methods accumulate.
Implicit in FederatedClient.__init__'s parameter list.
\(O(1)\)
Cost of swapping any one implementation. Because everything talks via protocols, a new backend doesn't ripple through call-sites — it just gets injected at the composition root.
orchestration/factories.py is the only file that mentions concrete classes; the rest of the codebase only knows protocols.
Note. Structural typing is what makes "8 protocols × ~3 implementations" combinatorially explorable: every \(o\) that satisfies \(\mathcal{P}\) is, by Liskov substitutability, a drop-in for every other such \(o\). The runner is closed under composition of sub-protocols; the type-checker is the only enforcement layer.
